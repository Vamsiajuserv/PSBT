## A. Executive summary

**Three earlier "defects" were caused by demo data, not the real code:**

- **Gateway anomalies are all mock.** Every FAILED (14), CREATED (13) and REFUNDED (4) payment order has an
  `order_ref` starting with "mock", generated by `mock_data.py:367` and attached to random bookings /
  donations [DB, CODE]. All **779 real orders are PAID**, each created and confirmed in the same request as
  its booking (`bookings.py:1015–1021`); **0** real bookings paid on a different day [DB]. The UI never
  calls the payments API (`PaymentsAPI` only defined in `client.js`), and **no code sets REFUNDED** [CODE].
  → Phase 2C "gateway donation" and "gateway refund" defects and Phase 2B "54 bookings" are **withdrawn**.
- **Waste "Recorded" is mock data.** Every committed version of `waste.py` creates sales as **"Paid"**
  [GIT: 7e0b424, 59ae5ec, f9ff14c, HEAD]; "Recorded" comes only from `mock_data.py:248` (random 25 %) and
  the model default [CODE].
- **The 10 "legacy" hundis are seed data** — `seed.py:557–560` creates `HUN-{year}-{i:05}` with
  `denomination="Mixed"` and no lines [CODE].

**Real defects that remain** (confirmed in code, reproducible with real flows):
- Hundi valuables counted as cash.
- Unpaid / Scheduled auctions counted as income; auction money forced to UPI on the auction date.
- Lot-auction payments missing from reports; lot parent duplicates buyer payments.
- UTC-date filters against IST business days.
- Closed-day view recomputes live.
- Payments without row locks; receipt numbers not unique.
- Dashboard and module stats disagree with Daily Closing.
- Typed hundi lines get a blank item type; the item master has no "Cash" item [CODE + DB: HUN-2026-00499,
  real user `counter1`, audit-logged].

**Status: NOT READY — BUSINESS DECISIONS REQUIRED.** Decision 3 blocks the Daily Closing formula;

## C. Evidence-based findings and remaining unknowns

**Hundi**
- Legacy no-line records: seed data in dev [CODE].
- "Mixed" denomination proves nothing — it is the **model default** (`models.py:287`) and the seed value [CODE].
- Blank-type line is real: HUN-2026-00499 created by `counter1` with a line typed "cash", approved by
  `s.ramachandra` then `committee1` [DB audit log].
- Rejected collections: excluded under decision 4. Correct & Resubmit clears approvals and keeps old amount
  and reason in `notes` [CODE].
- Deposits: status only, no amount; Bank Deposits report shows `counted_amount` [CODE].
- Admin classification path: reusing Correct & Resubmit gives an audit-logged history ("₹old → ₹new —
  Reason") [CODE]; its scope must be extended from Rejected-only to legacy records.

**Gateway**
- Real bookings call `create_order` + `verify_and_confirm` in the same transaction, so the booking's money
  time equals `payment_orders.paid_at` within one request [CODE]; mode comes from the counter's
  `payment_method` [CODE].
- Counting "PAID orders" as money rows could **double count** with the booking → the contract keeps the
  **booking** as the money row and uses the order only for the date.
- No duplicate-refund risk today (no refund code).

**Waste:** only mock data is "Recorded"; production check required (step 0).

**Receipts and concurrency**
- `next_code_seq` uses atomic `INSERT … ON CONFLICT DO UPDATE … RETURNING` on PostgreSQL 16 — safe across
  multiple app instances [CODE, DB].
- No duplicate receipts within or across tables in dev [DB].
- Partial unique indexes (`WHERE receipt_no IS NOT NULL`) supported on PostgreSQL 16 [DB version].
- Payment endpoints do not lock rows [CODE].

**Financial / IST consistency**
- Still using `func.date(<naive UTC>)`: `daily_closing.py`; `reports.py` (all collection reports +
  `_stamp`, `_range`, `_daily_summary`); `dashboard.py`; `analytics.py`; `waste.py` stats; `donations.py`
  stats; `misc.hundi_stats` [CODE].
- Frontend `Dashboard.jsx` and `Auction.jsx` use the browser's UTC date [CODE].
- Exports reuse report endpoints [CODE].
- Outstanding balances are not reported anywhere [CODE].

## D. Proposed financial calculation contract

`finance.collections(start, end)` → one row per money receipt, IST day windows. Every report, the
Dashboard, stats and exports read from it.

| Type | Qualifies as received | Amount | Date | Mode |
|---|---|---|---|---|
| Booking | `payment_status = Paid` (cancelled-but-paid stays; refund separate) | amount | `created_at` (= gateway confirm time today; use `payment_orders.paid_at` if a deferred online flow is added) | payment_method |
| Donation | not voided, not Material | amount | `created_at` | mode |
| Hundi cash | lines typed Cash / Coins; collection not Rejected (D4); **untyped / no-line amounts → "unclassified", not cash** (D1–2) | Σ lines | `collected_on` | Cash |
| Hundi valuables | never money | – | – | – |
| Single auction | `from_stock = false`, `payment_status = Paid` | current_amount | paid_at | payment_mode |
| Lot buyer | `auction_sales.payment_status = Paid` | amount | paid_at | payment_mode |
| Lot parent | **never money** | – | – | – |
| Open Sale | every row | amount | sold_at | payment_mode |
| Annadanam | every row | amount | coalesce(paid_at, created_at) | mode |
| Waste | `status = Paid` ("Recorded" pending step 0) | amount | coalesce(paid_at, created_at) | mode |
| Refund | every row | −amount | refund_date | mode |

**Rules**
- **Mode mapping:** Cash = "Cash"; Online = "UPI", "UPI/QR Code", "Online"; Card, Bank Transfer, Cheque as
  recorded; blank = Cash (existing rule).
- **Outstanding:** single = Completed + Verified + not Paid; lot = Pending `auction_sales` under a Verified
  parent; "awaiting approval" = Completed + Pending verification.
- **Refunds:** separate money-out row, never a void; returned item → "Returned — inspection" (D7–8).
- **IST day D:** `col >= D−1 18:30 UTC AND col < D 18:30 UTC`; date-only columns as-is; stored timestamps
  never changed.
- **Daily Closing:** expected drawer cash = opening + Σ cash rows that **enter the drawer** (depends on D3)
  − cash refunds. A closed day shows its stored snapshot as official, recalculation information-only.
